# คู่มือ Demo: ดู workflow ของ CMS

ใช้เปิดระบบทั้งชุดในเครื่องเดียวแล้วเดินดู workflow ตั้งแต่เขียนบทความจนถึงเผยแพร่ ใช้เวลาเดโมราว 10 นาที
สำหรับการขึ้นระบบจริง ดู [คู่มือปฏิบัติการ](../infra/runbooks/README.md) แทน

## เริ่มระบบ

ต้องมี Docker Desktop ที่เปิดอยู่ และ Git Bash บน Windows จากนั้นรันที่โฟลเดอร์โปรเจกต์:

```bash
bash infra/scripts/demo-up.sh
```

ครั้งแรกใช้เวลาหลายนาทีเพราะต้อง build image เมื่อเสร็จจะแสดงบัญชีทั้งหมด และเก็บไว้ที่
`infra/.local/demo-accounts.txt`

| Role   | Email             | รหัสผ่าน           |
| ------ | ----------------- | ------------------ |
| Author | `author@cms.test` | `Demo-Author-2026` |
| Editor | `editor@cms.test` | `Demo-Editor-2026` |
| Admin  | `admin@cms.test`  | ดูจากไฟล์ด้านบน    |

### เตรียม browser ก่อนเดโม

1. เปิด <https://localhost:8443> แล้วกด **Advanced** และ **Proceed** เพื่อยอมรับคำเตือนใบรับรอง
2. เปิด <https://media.localhost:8443> แล้วยอมรับแบบเดียวกัน หน้านี้จะแสดง error เป็น XML ซึ่งเป็นเรื่องปกติ
   ถ้าข้ามข้อนี้ การอัปโหลดและรูปภาพจะใช้ไม่ได้
3. เปิดหน้าต่างปกติหนึ่งบาน และหน้าต่าง Incognito หนึ่งบาน เพราะบัญชีในหน้าต่างเดียวกันจะแชร์ session กัน
   การแยกหน้าต่างทำให้สลับระหว่าง Author กับ Editor ได้ทันที

เข้าระบบครั้งแรกของแต่ละหน้าต่างจะมีประกาศความเป็นส่วนตัว ให้กด **I understand**

## ข้อมูลที่เตรียมไว้

| บทความ                         | สถานะ     | ใช้ทำอะไร                       |
| ------------------------------ | --------- | ------------------------------- |
| `Office move: first draft`     | Draft     | ของ Author ยังเขียนไม่เสร็จ     |
| `Getting started with the CMS` | In Review | ของ Author รอ Editor ตรวจ       |
| `Welcome to the new CMS`       | Published | อ่านได้ผ่าน public API อยู่แล้ว |

## เส้นทางเดโม

### 1. Editor ตีกลับ (หน้าต่าง Incognito, `editor@cms.test`)

1. ไปที่ **Content** จะเห็นบทความทั้งสามพร้อมสถานะ
2. เปิด `Getting started with the CMS` แล้วกด **Reject**
3. พิมพ์หมายเหตุ เช่น `Please add a closing paragraph.` แล้วกด **Reject** สถานะจะกลับเป็น Draft

### 2. Author แก้แล้วส่งใหม่ (หน้าต่างปกติ, `author@cms.test`)

1. ไปที่ **Content** แล้วเปิดบทความเดิม จะเห็นหมายเหตุของ Editor เป็นแถบด้านบน
2. สังเกตว่าปุ่ม **Publish** เป็นสีเทา เพราะ Author เผยแพร่เองไม่ได้
3. เติมข้อความในเนื้อหา แล้วกด **Save Draft** ตามด้วย **Submit for Review**
4. เมื่อส่งแล้วจะเห็นข้อความว่าอ่านได้แต่แก้ไม่ได้ เพราะบทความอยู่กับ Editor แล้ว

### 3. Editor เผยแพร่ (หน้าต่าง Incognito)

Reload หน้าบทความ แล้วกด **Publish** สถานะจะเป็น Published

### 4. ดูผลจากฝั่งเว็บภายนอก

นำ API key จาก `demo-accounts.txt` มาใส่ในคำสั่งนี้:

```bash
curl -k -H "X-API-Key: <API key>" https://localhost:8443/api/v1/articles
```

จะเห็นบทความเพิ่งเผยแพร่ ส่วนบทความที่ยังเป็น Draft จะไม่ออกมา ถ้าไม่ใส่ key จะได้ `401`
เอกสาร API อยู่ที่ <https://localhost:8443/docs>

### 5. Editor ถอนการเผยแพร่

1. กด **Unpublish** แล้วยืนยัน
2. รันคำสั่ง curl อีกครั้ง บทความจะหายไปทันที
3. แถบแจ้งเตือนด้านล่างซ้ายจะมีปุ่ม **Undo** อยู่ 60 วินาที กดเพื่อนำกลับมา ถ้าแจ้งเตือนก่อนหน้ายังค้างอยู่
   ปุ่มจะขึ้นหลังจากนั้นไม่กี่วินาที ปุ่ม Undo ในแถบเครื่องมือของ editor เป็นคนละปุ่ม ใช้ย้อนการพิมพ์เท่านั้น

บทความที่ Unpublished แล้วปล่อยไว้จะเผยแพร่ซ้ำทันทีไม่ได้ ต้องแก้เนื้อหาแล้ว **Save Draft** เพื่อให้กลับเป็น Draft ก่อน

### 6. รูปภาพ

ไปที่ **Media** แล้วกด **Upload** หรือลากไฟล์เข้ามา รูปจะถูกอัปโหลดตรงไปยัง storage และ worker จะสร้างขนาดย่อยให้
ถ้าเลือกไฟล์ที่เนื้อในไม่ตรงกับนามสกุล ระบบจะปฏิเสธ จะแทรกรูปในบทความก็ได้ด้วยปุ่ม **Image** ใน editor

### 7. ตั้งเวลาเผยแพร่ (ถ้ามีเวลา)

Editor เปิดบทความ `Office move: first draft` กด **Schedule...** แล้วเลือกเวลาล่วงหน้าสักหนึ่งถึงสองนาที
บทความจะเผยแพร่เองภายในราว 30 วินาทีหลังถึงเวลา

### 8. Admin (`admin@cms.test`)

- **Users** กด **Invite user** แล้วเปิด <http://localhost:8025> ซึ่งเป็นกล่องจดหมายจำลอง จะเห็นอีเมลเชิญพร้อมลิงก์ตั้งรหัสผ่าน
- **Audit Log** มีประวัติทุกการกระทำในเดโมนี้ และไม่มีใครแก้ไขได้
- **API Keys** กด **Revoke** ที่ `demo frontend` แล้ว curl ด้วย key เดิมจะได้ `401` ทันที ทำข้อนี้ไว้ท้ายสุด
  เพราะขั้นที่ 4 ต้องใช้ key นี้

## ข้อควรระวังขณะเดโม

- เข้าสู่ระบบได้ 10 ครั้งต่อนาทีจากเครื่องเดียว ถ้าขึ้น `Too many requests` ให้รอหนึ่งนาที
- ใส่รหัสผิด 5 ครั้งจะล็อกบัญชี 15 นาที ถ้าจะโชว์ข้อนี้ให้ทำหลังจบเดโม หรือเริ่มข้อมูลใหม่
- ไม่แตะหน้าจอ 30 นาทีจะถูกออกจากระบบ
- Audit Log จะมีรายการอยู่แล้วตั้งแต่เริ่ม เพราะการทดสอบและการเตรียมข้อมูลตอนเปิดระบบ ไม่ใช่ข้อผิดพลาด

## จัดการระบบ

เริ่มข้อมูลใหม่หมด เพื่อเดโมอีกรอบ:

```bash
bash infra/scripts/local-down.sh --wipe
```

จากนั้นรัน `demo-up.sh` อีกครั้ง

ปิดระบบโดยเก็บข้อมูลไว้:

```bash
bash infra/scripts/local-down.sh
```

| ปัญหา                        | ทางแก้                                                        |
| ---------------------------- | ------------------------------------------------------------- |
| อัปโหลดไม่ได้ หรือรูปไม่ขึ้น | เปิด <https://media.localhost:8443> แล้วยอมรับคำเตือนอีกครั้ง |
| สคริปต์บอก port ถูกใช้อยู่   | ปิดโปรแกรมที่ใช้ port 8080, 8443 หรือ 8025                    |
| คำสั่ง `docker` ล้มเหลว      | เปิด Docker Desktop แล้วรอให้พร้อมก่อน                        |
| ต้องการดู log                | `bash infra/scripts/compose.sh logs --tail=100 cms-api`       |

## ขอบเขตของเดโมนี้

ระบบทำงานด้วย container ชุดเดียวกับที่ออกแบบไว้สำหรับ production แต่ยังมีส่วนที่ต่างจากของจริง:

- ใบรับรองเป็น self-signed จึงมีคำเตือน และรหัสผ่านของ Author กับ Editor ตายตัว ใช้ได้เฉพาะเครื่องนี้
- อีเมลไม่ได้ส่งออกจริง แต่เข้า Mailpit
- ยังไม่มี monitoring และ alert และยังไม่เคยขึ้นบน VM จริง
