# Handoff: T-005

- **Ticket:** [T-005](../tickets/T-005-state-enforcement.md)
- **Commit:** `f8dce4d` red, `1962c1d` green และ commit ของ Handoff นี้

## สิ่งที่เสร็จ

- `docs/harness/state.json` เก็บ Ticket ที่ทำอยู่ ขั้นปัจจุบัน วันที่อนุมัติ และไฟล์ที่แก้ได้
- Hook ปฏิเสธ `red` ที่ยังไม่มีวันที่อนุมัติ และปฏิเสธ `green` ที่แก้ไฟล์นอกรายการ พร้อมบอกชื่อไฟล์
- `gate:self-test` รัน hook จริงกับ repo ชั่วคราว จับได้ทั้งสองกรณี รวมเป็น 30 แบบ
- กฎ Red ใหม่ใน `workflow.md`: โค้ดที่ยังไม่มีให้เป็นโครงที่ throw และ Red ของงานนี้ทำตามกฎนั้นเอง
- `init.sh` สำหรับเริ่มหน้าต่างใหม่ และ ADR-0018 บันทึกการเปลี่ยน gate

## ผลการตรวจ

- **Gate:** `pnpm gate` ผ่านครบ 18 ขั้น (2026-11-12) รวม E2E 13/13 ส่วน CVE พบระดับ low 1 และ moderate 1 ซึ่งไม่ถึงเกณฑ์ที่ทำให้ล้ม
- **Self-test:** `pnpm gate:self-test` จับได้ 30/30
- **Unit test:** `git-guard.test.mjs` ผ่าน 28/28 จากที่ Red ล้ม 10 กรณีแยกกัน
- **ลองจริงใน Claude Code:**
  - stage `zzq-outside.txt` แล้วสั่ง commit `green` ถูกปฏิเสธว่า "Outside the Contract of T-005: zzq-outside.txt"
  - ล้าง `approved` ชั่วคราวแล้วสั่ง commit `red` ถูกปฏิเสธว่า "The Contract of T-005 is not approved"
  - คืนไฟล์ทั้งสองแล้ว
- **`init.sh`:** รันใน Git Bash บนเครื่องนี้ได้ ติดตั้ง แสดงสถานะ และ `gate:fast` ผ่าน

## Review

ยังไม่ได้รีวิว ผู้ใช้เลือกได้ว่าจะรีวิวหรือไม่ และจะแก้ findings ข้อไหน

## สิ่งที่ยังไม่เสร็จหรือยังไม่ได้ตรวจ

- AI แก้ `state.json` เองได้ hook จึงพิสูจน์แค่ว่ามีการบันทึก ไม่ใช่ว่าคนอนุมัติจริง ตามที่ ADR-0018 ระบุ
- การล้าง `approved` และ `files` ตอนจบ Handoff เป็นกฎในเอกสาร ยังไม่มีอะไรบังคับ
- `init.sh` ยังไม่ได้ลองบน Linux หรือใน CI
- ADR-0018 รอ Tech Lead รีวิว
- ข้อ 9 การวัดพฤติกรรม AI ก่อนและหลังมี harness อยู่นอกขอบเขต

## บทเรียน

Hook ใหม่มีผลกับ commit `green` ของตัวมันเองทันที เพราะ hook อ่านโค้ดจากไฟล์ในเครื่อง ไม่ใช่จาก commit ล่าสุด
ต้องใส่ทุกไฟล์ของงานไว้ใน `files` ก่อน commit `green`
