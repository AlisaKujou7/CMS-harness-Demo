# T-003: Requirement Traceability gate สำหรับ FR

## Ticket

- **Requirement:** 02-SRS §11.3 (traceability matrix), §5 (FR ทั้งหมด)
- **ปัญหา:** Gate ทั้ง 17 ขั้นผ่านได้แม้ฟีเจอร์ในสเปกขาด เพราะไม่มีขั้นไหนเทียบงานกับรหัส requirement
- **ข้อมูลตั้งต้น (นับเมื่อ 2026-11-03):** SRS มี FR 64 รหัส เทสต์ 166 ไฟล์อ้างถึงแล้ว 53 รหัส เหลือ 11 รหัสที่ไม่มีเทสต์อ้าง:
  FR-AUDIT-02, FR-AUDIT-04, FR-AUTH-01, FR-AUTHZ-01, FR-AUTHZ-03, FR-AUTHZ-04, FR-CONTENT-10, FR-CONTENT-14, FR-CONTENT-16, FR-USER-03, FR-USER-08
- **Branch:** `feature/ci-requirement-traceability`

## Contract

**สถานะ:** อนุมัติแล้ว

### ขอบเขต

1. เพิ่มขั้น `traceability` ใน `pnpm gate` อ่านรหัส FR จาก `AIAGENT_POC/02-Software-Requirements-Specification.md` โดยตรง
   และไม่ผ่านถ้ารหัสใดไม่มีเทสต์อ้างถึงและไม่อยู่ในรายการยกเว้น ผลที่ไม่ผ่านต้องบอกรหัสที่ขาด
2. เพิ่มรายการยกเว้น ซึ่งทุกข้อต้องมีเหตุผล ถ้ายกเว้นรหัสที่ไม่มีอยู่ในสเปก หรือรหัสที่มีเทสต์อ้างแล้ว ต้องไม่ผ่าน
3. ไล่ 11 รหัสที่ขาด ทีละข้อ:
   - มีเทสต์ที่ตรวจเรื่องนั้นจริงอยู่แล้ว: เพิ่มรหัสในชื่อเทสต์
   - ยังไม่มีเทสต์: เขียนเทสต์ใหม่
   - ทดสอบอัตโนมัติไม่ได้ เช่น การเก็บ log 365 วัน: ใส่ในรายการยกเว้นพร้อมเหตุผล
4. เพิ่มกรณีใน `gate:self-test` ที่ฝังรหัสซึ่งไม่มีเทสต์ แล้ว gate ต้องจับได้

### นอกขอบเขต

- UR, NFR, SEC และ BR ซึ่งจะพิจารณาเป็น Ticket แยก
- การตรวจว่าเทสต์ที่อ้างรหัสอยู่แล้วทั้ง 53 รหัสตรวจเรื่องนั้นจริงทุกข้อ
- การรวมขั้นนี้เข้า CI จริง เพราะยังไม่มี remote ตัว workflow ไม่ถูกแก้ ยกเว้นต้องเพิ่มชื่อขั้นใน `pr-gate.yml`

### ไฟล์ที่แก้ได้

- `tools/gates/checks.mjs`, `tools/gates/checks.test.mjs`, `tools/gates/check.mjs`
- `tools/gates/run-gate.mjs`, `tools/gates/self-test.mjs`
- `tools/gates/traceability-exceptions.json` (ไฟล์ใหม่)
- `.github/workflows/pr-gate.yml`
- `cms-api/src/**/*.spec.ts`, `cms-api/test/**`, `cms-web/src/**/*.spec.ts*`, `cms-web/test/**`
- `docs/adr/0017-requirement-traceability-gate.md` (ไฟล์ใหม่), `docs/quality/gates.md`
- ไฟล์ใน `docs/harness/` ของงานนี้

**ห้ามแก้โค้ดระบบใน `src` ที่ไม่ใช่เทสต์** ถ้าเขียนเทสต์แล้วเจอว่าฟีเจอร์ขาดหรือมีบั๊ก จะหยุดแล้วแจ้งผู้อนุมัติ และเปิดเป็น Ticket ใหม่

### Definition of Done

- [ ] มี commit `red` และ `green` ของตัวตรวจ
- [ ] `pnpm gate` มีขั้น `traceability` และผ่าน โดยทั้ง 64 รหัสมีเทสต์อ้างหรืออยู่ในรายการยกเว้นพร้อมเหตุผล
- [ ] ลบรหัสออกจากเทสต์แล้ว gate ไม่ผ่าน และบอกรหัสนั้น
- [ ] `pnpm gate:self-test` จับกรณีใหม่ได้
- [ ] Handoff แสดงตารางว่า 11 รหัสจบแบบใด

### ความเสี่ยง

- **การอ้างรหัสไม่ได้พิสูจน์ว่าทดสอบจริง:** gate ตรวจได้แค่ว่ามีการอ้างถึง AI อาจเติมรหัสในเทสต์ที่ไม่เกี่ยวเพื่อให้ผ่าน
  จึงกำหนดว่าการเพิ่มรหัสใน 11 ข้อนี้ต้องอธิบายใน Handoff ว่าเทสต์นั้นตรวจอะไร และต้องระบุข้อจำกัดนี้ใน ADR
- **รายการยกเว้นกลายเป็นทางลัด:** ทุกข้อต้องมีเหตุผล และ Handoff ต้องแสดงให้ผู้อนุมัติเห็นทั้งหมด
- **เจอฟีเจอร์ขาดจริง:** gate จะไม่ผ่านจนกว่าจะมีการตัดสินใจ งานนี้จึงอาจต้องหยุดกลางทาง
- **การเพิ่ม gate เป็นเรื่องของ Tech Lead:** ตาม 08-GIT-WORKFLOW §16.1 จึงบันทึกเป็น ADR สถานะรอรีวิว เช่นเดียวกับ ADR-0014

### การอนุมัติ

- **ผู้อนุมัติ:** ผู้ใช้ ผ่านแชตของ Claude Code ("อนุมัติ")
- **วันที่:** 2026-11-03

```text
SyntaxError: The requested module ./checks.mjs does not provide an export named findUntracedRequirements

```
